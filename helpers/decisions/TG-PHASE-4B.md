## 2. Core flows and document delivery as built (WP-1b, `helpers/SPEC.md` §2 / §5 / §8 / §18)

- **`registerFlow(name, { start(seed, fctx) → step, next(state, input, fctx) → step, onDone?(state, fctx), ttl_min? })`** in `helpers/core/15_flows.js`; registry bucket `flow` in `02_registry.js`. Name `^[a-z][a-z0-9_-]{0,31}$`; one active flow per chat.
- **Step**: `{ prompt: html, keyboard?: rows of { text, value } | { text, url }, expect: 'button' | 'text' | 'any', state, done?: true, result?, pause?: true }`. **Input**: `{ type: 'button', value }` | `{ type: 'text', text }` | `{ type: 'resume', … }`. Buttons carry `fl:<step>:<value>`; the `fl` callback prefix is registered by the core and reserved.
- **Helpers a pack calls**: `flowStart(chatId, name, seed)` (replaces a running flow, audit `flow_replaced`), `flowActive(chatId)`, `flowResume(chatId, input) → { done, error }`, `flowCancel(chatId)`. Router: `flowClaimText(ctx)` gives the active flow first claim on free text and `fl` callbacks — after commands, before message handlers and before a request opens. `/cancel` is registered in `15_flows.js`. A `pause: true` step keeps state (`expect = paused`) and releases the text claim until `flowResume`.
- **State**: `Flows` tab (`chat_id flow step expect state_json updated_at expires_at`), `state_json` ≤ `FLOW_STATE_MAX_CHARS` (40 000, a larger step throws and the flow is not advanced), expiry after `ttl_min` (default `FLOW_DEFAULT_TTL_MIN` 1 440); `expireFlows()` in the sweep tells the owner once and audits `flow_expired` per row; snapshot provider `flows_active`.
- **Documents**: `tgSendDocument(chatId, { driveFileId | blob, filename?, caption?, replyTo?, silent? })` and `tgSendOwnerDocument(spec)` (multipart `sendDocument` via `tgApiMultipart`); ≤ `DOCUMENT_MAX_BYTES` (52 428 800), a larger Drive file is sent as its link and audited `document_too_large`. **`reply.payload.drive_file_ids?: { <label>: <drive file id> }`** — ≤ `REPLY_MAX_DOCUMENTS` (10) labels, label `[A-Za-z0-9 _.()-]{1,60}`, validated in `09_mailbox.js`; each is sent as a silent captioned document after the reply text. Tests: `helpers/tests/core_flows.test.js`.

## 3. The six payload schemas and the Place / shortlist fields as built (WP-3d, WP-2g-engine)

- **Files**: `helpers/packs/tour-guide/schemas/tour-guide-<kind>.schema.json` for kinds `shortlist`, `trip-facts`, `plan-digest`, `profile-summary`, `prefs-review`, `places-digest` (file names use hyphens; envelope types use underscores). `schemas/index.mjs` exports `PAYLOAD_KINDS = { prefs_review: 'prefs-review', shortlist: 'shortlist', trip_facts: 'trip-facts', plan_digest: 'plan-digest', profile_summary: 'profile-summary', places_digest: 'places-digest' }` and `validatePayload(type, payload) → { ok, kind, errors }`; `helper.json` `envelope_types` lists the six and `node helpers/tools/bundle.mjs tour-guide --check` passes. Shapes: the pack README's payload table.
- **Required fields**: `trip_facts` → `trip, found, missing`; `shortlist` → `trip, run_id, round, groups, more` (+ optional `decided`); `plan_digest` → `trip, build_id, verified_on, days, later, drive`; `places_digest` → `destination, places`; `prefs_review` → `v, kind, vocab, batch_id, items, held_back, more` (exactly the prefs kit's `buildReview` payload); `profile_summary` → `text` (+ `dimensions_count`, `updated`). Digests are capped at 60 000 characters so they fit one envelope.
- **Place** (`tour-guide-place.schema.json`): required `v, id, place_id, name, category, tags, status, activity, priority`; statuses `candidate · scheduled · saved-for-later · rejected`; places-repository fields `destination`, `history[] = { trip, on, event: shortlisted | chosen | later | skipped | scheduled | visited | rated_up | rated_down | checked, note? ≤ 120 }` (≤ 200, oldest first), `last_researched`, `last_verified`; Gem Funnel fields `gem_score` 0–100, `gem`, `obscurity` 0–1, `local_mentions[] = { ref, language (BCP 47), kind: editorial | community | local-language }` (≤ 20), `flags[]` ⊆ `unproven | tourist_oriented | closed_day_conflict` (≤ 5) — exactly what `gems.toPlaceFields()` emits. No Google field (hours, rating, review count, website, address, business status) has a slot in the Place.
- **Shortlist item**: `n, slug, name, why_you, fit, est_minutes, area, maps_url, labels, place_id?, new?, gem?, gem_line? (≤ 200), seen_before?, changes?, dims?`; groups `activities | food` with `gems_wanted` / `gems_shown` (0–8), ≤ 20 items per group, slugs unique across groups, `gems_shown` ≤ the group's 💎 items (semantic check in `schemas/index.mjs`).
- **Planner choices**: `planTrip({ …, choices?: { picks?, later?, skip? } })` (`planner-choices.mjs`: `normalizeChoices`, `applyChoices`, `POOL_STATUSES`, `CHOICE_LISTS`, `OWNER_CHOICE_REASON`); `later` slugs become status `saved-for-later` and a "Saved by you" item (`SAVED_BY_YOU`, the third named Later list, code `owner_choice`), `skip` → `rejected`; a replan reuses `plan.choices`. Later-list codes gained `owner_choice` and `not_shown`.

## 4. The prefs kit's `interview` command as built (WP-2f)

- **CLI**: `node helpers/kits/prefs/index.mjs interview --vocab travel --bank travel --held <DIR> --profile <FILE> [--ledger <FILE>] [--now <ISO>] [--max 8] <answers.json>`; library `interview` (alias `runInterview`). Exit codes 0 ok, 1 usage, 2 refused (unreadable bank, refused profile write).
- **Input, three shapes detected by shape**: the answers object `{ version: 1, answers: [{ qid, dimension, value, polarity, kind: pick | multi | scale | text }] }` (≤ 200); a request payload carrying it as `interview`; or the core's whole `request` envelope whose `payload.interview` holds it — then `created_at` is the decision time and `interview:<request id>` the decision ref (`decided_at` = `created_at` + the answer index in ms, later answer wins, re-run byte-identical). Without an envelope `--now` is required.
- **Bank**: `helpers/kits/prefs/presets/travel.interview.json` (39 questions, 13 sections incl. `hidden-gems`), schema `helpers/kits/prefs/schemas/travel.interview.schema.json`; `sections[] = { id, title, questions[] }`, question `{ qid: <section>-NN, text ≤ 200, kind, dimension, options: [{ label ≤ 24, value, polarity }], skip_ok }`. Vocabulary `presets/travel.vocab.json`: 22 dimensions incl. `climate` (`heat`, `cold`, `altitude`, `humidity` values) and the Gem Funnel's `gem_appetite` (1–5, default "3"), `off_track_minutes`, `rough_edges` (`cash_only · no_english_menu · queues · no_reservations · standing_room`).
- **Result**: `{ ok, errors, decided_at, ref, applied, already, held, rejected, superseded, warnings, review, profile_summary, profile_entries }` — `review` is a `prefs_review` payload built from this interview's held candidates only; `profile_summary` is plain text ≤ 1 200 characters (the `profile_summary` envelope's `text`). Picks become owner decisions only when no suspect or outvoting evidence exists; text answers stay held; an answer off the bank is applied with a `warning` (the tapped triple is what counts).

## 5. Request kinds — the contract Phase 5's core emits and WP-4d's skills answer

`req_<id>.json` → `payload.kind`; `payload.text` is always the owner's words, `payload.chat` the originating message. This table supersedes `helpers/decisions/TG-PHASE-4.md` §2 and is mirrored in the private repo's `skills/README.md`.

| `kind` | Skill | Extra payload fields (all optional) | Envelopes back |
|---|---|---|---|
| `research` | `trip-research` | `trip`, `scope`: `new` (default) \| `more` \| `intake`; `like` (slug, "more like X"); `decided` (slugs already picked, saved or skipped — `more` never repeats them, and the Gem Funnel skips them when filling 💎 floors); **`gems_only: true`** (with `scope: more`: only 💎 candidates, the *More gems* round); **`seeds: [names]`** (free text or `/seed`, enter the funnel as stream `owner_seed`); `destination`, `start_date`, `end_date`, `lodging`, `booked` (confirmed intake facts) | `intake`: `trip_facts` (+ a `reply` listing the facts to confirm, edit or reject); `new` / `more`: one `shortlist` round (activities, then food; 💎 items carry `gem_line`; groups carry `gems_wanted` / `gems_shown`) plus the same round as `shortlist-<run_id>.json` in the trip's Drive folder. `scope: new` on a known destination lists known places first (`seen_before`, `changes`), moves closed ones to Later with a reason, then the new candidates. Sets the trip `researched` → `choosing` |
| `plan` | `plan-days` | `trip`, `picks` (slugs chosen: only they are planned), `later` (→ `saved-for-later`, "Saved by you", reason `owner_choice`), `skip` (→ `rejected`), `deliverables` (default `["plan"]`; `plan`, `notes`, `brochure` — notes and brochure run in the same run, in that order), `seed`, `allow_over_budget` (only from the owner's words), `show_google_content` (remembered in `profile_overrides`) | `plan_digest`; a `reply` with the day list, Later reasons, warnings, the notes count and `drive_file_ids` (notes and brochure PDF) so the core sends the files; `places_digest` when the places repository changed. Writes `chosen | later | skipped | scheduled` history and choice evidence (`choice:<trip>:<slug>`, `--min-support 2`); status `planned`, then `delivered` once notes and brochure are sent |
| `replan` | `plan-days` | `trip`, `dates` (required), `promote` (slugs onto the one date given), `demote` (slugs out of the plan), `reason` | the same for those dates only; no `drop` / `add` (§1 item 7) |
| `notes` | `place-notes` | `trip`, `places` (default: every scheduled or saved place without a current note) | a `reply` with the count written |
| `brochure` | `brochure-build` | `trip`, `build_id` (default latest), `show_google_content` | a `reply` with `drive_file_ids` (HTML and PDF) |
| `prefs` | `prefs-build` | `window_days` (default 365); **`interview`** (the answers object, § 4 — the kit's `interview` command, one call); **`review: { trip, items: [{ slug, rating: up \| down \| skipped, calibration?: longer \| shorter \| right }] }`** (the post-trip review: `rated_up` / `rated_down` history, prefs evidence, calibration) | `prefs_review` (held candidates with `pf:<cid>:y|e|n` buttons) and `profile_summary`; a `places_digest` after a `review` |
| **`places`** | `trip-check` | `scope`: `check` \| `list`; `destination`; `slugs?` | one `places_digest` (`list`: the repository for that destination; `check`: re-verified, digest only when something changed). The same check runs weekly on upcoming trips |
| `message`, `ask` | `chat` | — (the core's own kinds, SPEC §3) | a `reply`; anything that changes a plan becomes a hand-off, never an edit |

A skill fired for a kind it does not own appends one line to `log/` and ends. `trip` missing → resolved from `payload.text` against `trips/`; with exactly one trip not `done`, that one; otherwise the skill asks which trip (the only question a skill asks). Every `reply` fits one Telegram message (≤ 4 000 characters, ≤ 40 lines).
