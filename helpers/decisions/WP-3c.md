# WP-3c decisions — Plan → brochure model

Defaults chosen while building `packs/tour-guide/brochure-map/` (no questions asked; each can be revisited).

1. **Info warnings.** `warn` and `alert` warnings go to the day's "Mind" block, sorted alert → warn → info. An `info` warning that names a stop of that day becomes that stop's rail `note` (several are joined); an `info` warning naming no stop of the day stays as an info line (the kit renders it with an info icon). Nothing is dropped. Warnings are capped at the kit's 12 per day, least severe cut first.
2. **`hours_today` only when unambiguous.** The kit uses a card-level `hours_today` in preference to its own per-day lookup, so a place visited on two weekdays with different lines would show the wrong hours on one of them. `hours_today` is set only when every visit date of the place shares the same weekday line; otherwise it is omitted and the kit derives the line per day from `hours`.
3. **`closed_days`** come from Google's weekday lines (`"Monday: Closed"`, case-insensitive), in the lines' order. With no lines but periods, a weekday with no opening period is closed (Monday first); any period without a `close` means open 24/7 → none. No hours at all → none ("hours unknown").
4. **`show_google_content: false`** (the open owner question, decisions TG-PHASE-2 §4) removes every field read from Places from the cards: `address`, `hours`, `hours_today`, `closed_days`, `rating`, `review_count`, `website`, `business_status`, `fetched_on` (and the snapshot's `maps_uri`). It keeps `place_id` (may be kept indefinitely) and sets `maps_url` to our own Maps URL built by the Maps kit's `placeUrl({ name, placeId })`. It appends a practical section "Verify before you go" (text dated with the plan's `verified_on`, one item per card with "last checked <snapshot date>" and the Maps link; split every 30 items), and forces `attribution.google = false`. Default stays `true` (show, with the attribution block), as TG-PHASE-2 §4 says until the owner answers.
5. **Coordinates** (`snapshot.location`) are kept on cards in both modes: the kit uses them only to draw the schematic route sketch (SVG positions, never printed as numbers), and the brochure is a build output. If the owner's answer also covers coordinates, drop `lat`/`lng` in `brochure-map-cards.mjs` under `showGoogle` (one line).
6. **`maps_url`** = the snapshot's `maps_uri` when Google content is shown and present, else `placeUrl({ name, placeId })`. Lodging always gets `placeUrl({ name, address, placeId })` (owner data, not Google content).
7. **`fetched_on`** is the snapshot's `fetched_at` converted to a date in the trip's time zone (`Intl`), falling back to the UTC date when the zone is invalid.
8. **Card name** is our Place `name` (owner/research), not Google's `display_name` (used only when the Place has no name). **Category** is capitalised with hyphens as spaces. **Tagline** is the Place's `why_fit` (clipped to 300).
9. **Which places get a card:** every place referenced by a stop, a meal `at`, a leg endpoint, a warning or a Later item, in that order of first appearance (days in date order, then Later lists). Other input places (rejected, unreferenced) are left out. A stop whose place is unknown **throws** (contract breach); an unknown slug on a meal / warning / leg is dropped, and on a Later item becomes a name-only item.
10. **Attribution** = the union of the PlaceNote and VisitEstimate sources **of places in the brochure** (so rejected places' research does not appear), notes first then estimates, deduplicated by URL key (scheme and host lower-cased, fragment and one trailing slash dropped, query kept). First title wins; the latest `accessed` date is kept; `supports` phrases are merged (`"tickets; visit length"`). Estimate sources get `supports: "visit length"`. A source without a title gets host + path as its title (the kit lists only titled sources). Cap 100 (kit limit). Each card also carries its own sources (cap 12) with the same titles, so the kit's url+title dedupe never lists one twice.
11. **Generator** defaults to `Tour Guide · brochure-map`; `attribution.note` says when Google fields were read (default mode) or that none are printed (hidden mode).
12. **Days with no stops** are not brochure days (the kit requires ≥ 1 stop); they become a "Free days" practical section (date + the free blocks' notes, or "No stops planned — a free day."). A plan with no stop at all throws.
13. **Day routes.** DayPlan `day_url` has no field in the brochure day, so a "Day routes" practical section lists one Maps link per day that has one (transit days usually have none).
14. **Theme** defaults to the first two stops' names ("A and B, and more") when the DayPlan has none. The day's `lodging` is the name of `lodging_end` (the night's bed). A meal `at: "lodging"` is named after `lodging_start` for breakfast, `lodging_end` otherwise.
15. **Booked text** = the stop's `booked`; else, when the Place has a `booking` for that date, "Timed entry HH:MM, booked (ref …)".
16. **Leg modes** TRANSIT→transit, WALK→walk, DRIVE→drive, BICYCLE→bike, anything else→other; `line`, `maps_url`, `depart_at`, `arrive_at`, `distance_m`, `note` copied.
17. **Limits.** A day with more than 14 stops throws (the planner caps clusters at 10). Legs, meals, free blocks, Later lists/items and practical sections/items are cut at the kit's maxima; every string is clipped to the schema's 300 / 4000 characters with an ellipsis.
18. **`verified_on`** (trip) = `options.verified_on`, else the latest DayPlan `verified_on`, else `built_on`; `built_on` = `options.built_on`, else `plan.built_on`. Places default to `plan.places` when `places` is not passed. Snapshots may be an array or an object; per place, the record from `plan.build_id` wins, else the most recently fetched.
19. **Later lists:** empty lists are dropped (kit needs ≥ 1 item); an empty reason falls back to a phrase per `code`; `from_date` becomes the note "Taken off the plan for <date>."
20. **PDF.** The kit exposes `renderPdf`, so `renderPlanPdf(args, outPath, opts)` exists; when `pdfAvailable()` is false it returns the HTML with `pdf: null, available: false` and writes nothing. `renderPlan` returns the brochure model (not the kit's prepared one) plus the kit's warnings.
21. **Sample input** (`brochure-map-sample.mjs`, 92 lines): five places rather than "4–5 + two Later items" from separate places — two scheduled on day 1, one on day 2, two in "Didn't fit" — so it stays small; an empty "Next time" list exercises the drop rule. Invented city Harrowmere, `Etc/GMT-2`, `Fixture…` place ids, reserved domains.
