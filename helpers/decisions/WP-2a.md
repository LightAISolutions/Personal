> Work package 2a of Phase 2 (`helpers/prompts/TG-PHASE-2.md` §2). Kit: `helpers/kits/maps/` (contract: its README). Status: `helpers/status/WP-2a.md`. Dates are 2026-10-01 unless stated. ## Findings the owner and later phases must know

**F1 — Plan fact 7 (caching) is only half right; the GoogleSnapshot design must change.** Read on 2026-10-01:
- Google Maps Platform Service Specific Terms, https://cloud.google.com/maps-platform/terms/maps-service-terms (page lists "Last modified June 10, 2026"):
  - §A.3 "Google ID Caching. Customer may cache the Google ID values from the Services that return such field and allow caching, in accordance with its Documentation. For example, Customer may cache (a) place_id from Places API, Directions API, Geolocation API and Routes API, …"
  - §14 "Places API (Legacy and New)" → 14.3 "Caching. Customer may temporarily cache latitude and longitude values from the Places API for up to 30 consecutive calendar days, after which Customer must delete the cached latitude and longitude values."
  - §19 "Routes API" → 19.3 "Caching. Customer may temporarily cache latitude (lat) and longitude (lng) values from the Routes API for up to 30 consecutive calendar days, after which Customer must delete the cached latitude and longitude values."
- Google Maps Platform Terms of Service, https://cloud.google.com/maps-platform/terms ("Last modified August 26, 2026"), §3.2.3: "(a) No Scraping. Customer will not export, extract, or otherwise scrape Google Maps Content for use outside the Services. For example, Customer will not: (i) pre-fetch, index, store, reshare, or rehost Google Maps Content outside the services; … (iii) copy and save business names, addresses, or user reviews; …" and "(b) No Caching. Customer will not cache Google Maps Content except as expressly permitted under the Maps Service Specific Terms."
- Places API policies, https://developers.google.com/maps/documentation/places/web-service/policies ("Last updated 2026-09-28 UTC"): "the place ID, used to uniquely identify a place, is exempt from the caching restrictions. You can therefore store place ID values indefinitely."

So: the 30-day clause **does** apply to Places API (New) (§14 is titled "Legacy and New") and to the Routes API, but **only to latitude/longitude**. Hours, rating, review count, website, address and names have **no** caching permission. Plan §4.4 keeps them in a `GoogleSnapshot` "purged after 30 days" in the state Sheet — that is not covered. The kit's default is therefore: place ids forever (in the caller's own data), lat/lng ≤ 30 days, all other Google content **build-scoped** (stripped at the next `purge`, default `contentMaxAgeHours = 0`). Consequences for Phase 3/4/5 (coordinator to carry into `TG-PHASE-3.md`): the state Sheet should hold place ids and our own notes, not Google content; Lane A `/place` answers that need hours or ratings should fetch live (Apps Script with the optional `MAPS_API_KEY`) or say "as of the last plan"; whether a delivered brochure/PDF in Drive that shows hours and ratings counts as "storing Google Maps Content" is an open question for the owner — the conservative reading is that it is display to the end user with attribution, refreshed per build, which plan §5.7 already does. Not legal advice; the owner decides.

**F2 — The credential is injected only through the proxy tunnel; header type confirmed by the call.** The first live attempt used a transport bug (`agent: false` made Node ignore `createConnection`, so the request went **directly** to Google, around the proxy). Google answered **HTTP 403 PERMISSION_DENIED** "Method doesn't allow unregistered callers … Please use API Key or other form of API consumer identity" — i.e. no key at all. One retry with `curl` (which tunnels through `HTTPS_PROXY`) on the free Text Search Essentials (IDs Only) SKU returned **HTTP 200**. After fixing the transport (regression test `kit_maps_transport.test.js` "CONNECT tunnel") the kit's own tunnel returned 200 as well. A key injected as `Authorization: Bearer` would have been rejected by Google as an invalid OAuth token, so the 200s confirm the credential arrives as an API-key header (`X-Goog-Api-Key`, empty prefix) on both `places.googleapis.com` and `routes.googleapis.com`. Lesson recorded in the transport's header comment: in Claude Code cloud environments a **direct** connection to Google is possible and silently carries no key — always tunnel through `HTTPS_PROXY`.

**F4 — Plan fact 2 corrections** (SKU details page, "Last updated 2026-09-30 UTC"): `businessStatus` is a **Pro** field, not Essentials; Place Details `photos` are in the free **IDs Only** SKU (Text Search `places.photos` is Pro); Text Search has **no** non-ID Essentials SKU — `location` / `formattedAddress` in a Text Search mask bill **Pro**. Pricing page ("Last updated 2026-09-28 UTC") also lists Text Search Enterprise + Atmosphere at $40 / 1,000 (free 1,000). Routes Pro triggers: 11–25 intermediates, `optimizeWaypointOrder`, `TRAFFIC_AWARE` / `TRAFFIC_AWARE_OPTIMAL`, location modifiers; Enterprise: two-wheeler, tolls, traffic on polylines. `TRANSIT` is not a Pro trigger.

**F5 — Grounding Lite spike (time-boxed, ~2 minutes).** `https://mapstools.googleapis.com/mcp` is reachable from this environment: MCP `initialize` → HTTP 200 (server "StatelessServer", protocol 2025-06-18) and `tools/list` → `search_places`, `lookup_weather`, `compute_routes`, `resolve_names`, `resolve_maps_urls`, both **without a key**. No tool was called: tool calls need a key (billable "Maps Grounding Lite" SKU) and the Claude HQ credential covers only the Places and Routes hosts. To use it from routines the owner would add `mapstools.googleapis.com` to the credential's host list and allow the Grounding Lite API on the key. Not on the critical path (plan fact 12): it has no opening hours or transit.

**F6 — `node helpers/kits/<kit>/` does not work.** Node resolves a bare directory to `index.js` (or package.json `main`), never `index.mjs`. SPEC §16 promises `node helpers/kits/<kit>/ <command>`; the working form is `node helpers/kits/maps/index.mjs <command>`. Request in the status file.

## Defaults chosen

| # | Choice | Default taken | Why |
|---|---|---|---|
| 1 | Tier names | `essentials`, `pro`, `enterprise`, `enterprise_atmosphere` (Place Details); `ids_only`, `pro`, `enterprise` (Text Search) | Mirror Google's SKU names; Text Search has no non-ID Essentials SKU (F4) and the brief asks for Pro + Enterprise; IDs-only is free and useful for cheap re-lookups |
| 2 | Mask contents | Cumulative per tier; Enterprise = hours (regular + current), phone, price level/range, rating, count, website on top of Pro (names, types, status, Maps URI, time zone, accessibility) on top of Essentials (id, location, addresses, types, viewport); Atmosphere adds editorial/review summaries, reviews and a few amenity flags | What plan §4.4 / §5.7 need per stop; reviews only in the Atmosphere mask so `place-notes` alone pays for them (plan fact 2) |
| 3 | SKU of a Routes call | Decided from the request features the kit exposes (not from the mask): Pro iff optimize / > 10 intermediates / `TRAFFIC_AWARE*` | Routes bills by features; Enterprise features and location modifiers are simply not exposed |
| 4 | Default monthly ceilings | 80 % of each free cap (Essentials 8,000 · Pro 4,000 · Enterprise 800 · Atmosphere 800; IDs-only 2,000 as a loop guard) | "At or below the free caps"; 20 % headroom for anything else using the same key (e.g. Apps Script `MAPS_API_KEY`); a normal trip (plan §8) is ~150 Enterprise calls |
| 5 | When a call is counted | On send (reserve before the request), failures still count and are annotated `failed` | A loop of failing calls must also hit the stop; over-counting by a few is harmless, under-counting is not |
| 6 | Route Matrix counting | Requested elements (origins × destinations), whole matrix checked against the remaining ceiling before the first chunk | Google bills elements returned; requested ≥ returned is the safe side; never leave a matrix half-fetched for budget reasons |
| 7 | Over-cap matrices | Split automatically (`chunk: true`); `chunk: false` refuses with `BAD_INPUT` | Brief: "chunk or refuse"; the planner usually wants the whole matrix |
| 8 | Chunk shape | Keep all destinations (≤ cap, ≤ 49 with ids) per request, then as many origins as fit | Simple, every element covered once, indexes remapped to global |
| 9 | Billing month | `America/Los_Angeles` calendar month (`tz` stored in the ledger) | Inference: Cloud Billing months run on Pacific time; using UTC would reset the counter 7–8 h early each month |
| 10 | Ledger persistence | JSON file named by the caller (`ledgerPath` / `--ledger` / `MAPS_USAGE_LEDGER`), atomic tmp + rename; a client refuses to start without one unless `allowMemoryLedger` (tests) | Routines run in ephemeral containers; the private repo keeps the file (e.g. in a memory directory) and commits it with the run's memory |
| 11 | Snapshot retention | place_id until the record is dropped; record dropped after 30 days; `content` stripped at every purge (`contentMaxAgeHours` 0, overridable); `latLngMaxDays` cannot exceed 30 | F1 |
| 12 | Snapshot storage | JSON store named by the caller (`MAPS_SNAPSHOT_STORE`), never in a public repo | Same as the ledger; keeps Google content out of git |
| 13 | Transport | Own `CONNECT` tunnel over `node:http` + `node:tls` when `HTTPS_PROXY` is set (NO_PROXY honoured), direct `node:https` otherwise; TLS trust from `NODE_EXTRA_CA_CERTS` (set by the environment) | Zero dependencies, works on any Node 22 without `NODE_USE_ENV_PROXY`, and the tunnel is what gets the key injected (F2). `NODE_USE_ENV_PROXY=1` and `https.Agent({ proxyEnv })` both worked for a plain HTTPS GET on Node 22.22, but they depend on the minor version and on how the process is started |
| 14 | Key handling | No key in Claude Code cloud; optional `apiKey` from the caller elsewhere, sent as `X-Goog-Api-Key`; never read from files, never logged, never in errors | Brief |
| 15 | Smoke landmarks | Text Search "Eiffel Tower, Paris" → Place Details on the result → WALK route to "Arc de Triomphe, Place Charles de Gaulle, Paris" | Famous public landmarks in one walkable city; one call per required API; address destination avoids a fourth (Text Search) call |
| 16 | Network commands in the CLI | `details`, `search`, `route`, `matrix`, `smoke` need `--live` **and** a ledger, else exit 2 | Nothing reaches Google by accident; every live call is counted in a persistent file |
| 17 | Retries | None in the kit | The caller decides; a retry loop inside the kit would hide budget use |
| 18 | Maps URLs | `api=1` URLs, `encodeURIComponent` for every value, `%7C` between waypoints, `*_place_id` when known, ≤ 9 waypoints, none for transit | Maps URLs docs; 9 is the lowest per-platform limit; transit directions ignore waypoints |
| 19 | File names | `lib/maps-*.mjs`, `fixtures/maps-fixture-*.json` | Unique basenames across the repo (four kits are built in parallel); `index.mjs` / `README.md` are SPEC §16 names |
| 20 | Fixtures | Hand-written in the real API shapes for the invented city "Velmora" (coordinates in open ocean, ids prefixed `Fixture`, `example.com` URLs, a phone string that cannot match a phone pattern) | Public repo; boundary check |
| 21 | `optimizeWaypointOrder` with < 2 intermediates | Refused (`BAD_INPUT`) | It would bill Pro for nothing |
| 22 | Grounding Lite | Feasibility only (F5); no client built | Optional, off the critical path |
