## 2. Subtree vs clone-at-run (Step 3)

**Decision: the `git subtree` pin stays** (plan §4.3 default). Measured 2026-10-01 in the Claude HQ environment against a scratch `helpers-dist` built from this phase's tree; full table and the procedure in `helpers/SPEC.md` §15, repeated in the template's `vendor/helpers/README.md` and `repository-information/DEV-SESSION.md`.

| | subtree pin at `vendor/helpers/` | shallow clone at routine start |
|---|---|---|
| Size | 54 files / 488 KB in the private repo, ≈ 0.9 MB `.git` for the whole skeleton | nothing committed; ≈ 1.3 MB fetched per run |
| Time | `subtree add` 0.14 s, `subtree pull` 0.24 s (local bare repo) + ~1 s for a GitHub fetch | ≈ 2.0 s per run (sparse shallow clone 1.37 s + sparse-checkout 0.62 s); a full shallow clone of `main` is 1.07 s / 3.9 MB |
| Offline | works | the run has no tools (clone fails immediately against an unreachable host) |
| Pin bump in `git diff` | `git diff --stat <before> HEAD -- vendor/helpers` lists the changed files; the squash commit carries `Squashed 'vendor/helpers/' changes from <old>..<new>` with a `git-subtree-split` trailer | not in git at all |

The clone saves 0.5 MB per private repo and costs determinism, offline behavior and reviewability; the measurement did not clearly favor it. Routines never bump the pin; a development session does, at most once per session, with `/update-helpers`.

## 3. Defaults chosen in this phase

| # | Choice | Default taken | Why |
|---|---|---|---|
