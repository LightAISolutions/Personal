## Decisions

### Maps kit

1. **Nearby Search tiers are `pro`, `enterprise`, `enterprise_atmosphere`; there is no `ids_only` or `essentials` tier.**
   - Why: the pricing and SKU pages list only Nearby Search Pro, Enterprise and Enterprise + Atmosphere. `places.id` in a Nearby mask bills Pro, so the Pro mask carries it and the mask-tier proof (`highestTier(mask) === tier`) still holds. Stream 2's free name → id resolution stays on Text Search `ids_only`.
2. **Nearby masks equal the Text Search masks of the same tier, minus `nextPageToken`.** Pro: id, displayName, formattedAddress, location, types, primaryType, businessStatus, googleMapsUri. Enterprise adds rating, userRatingCount, regularOpeningHours, websiteUri, priceLevel. Atmosphere adds the Details Atmosphere fields.
   - Why: the brief asks for results "in the same shape `searchText` returns", and the engine screens both streams with one code path. A test pins the equality. Fixed frozen constants, no caller field lists (WP-2a invariant: one call = one SKU).
3. **Text Search gains `enterprise_atmosphere`; the search Atmosphere masks reuse the Details Atmosphere field list** (`editorialSummary`, `reviewSummary`, `reviews`, `generativeSummary`, `goodForChildren`, `servesVegetarianFood`, `reservable`, `restroom`, `outdoorSeating`, all with `places.`). The existing `ids_only` / `pro` / `enterprise` masks are unchanged.
   - Why: one list to keep in step; every field is classified by `fieldTier`, so the proof test covers it.
4. **`generativeSummary` joins the Place Details Atmosphere mask.** It is an Atmosphere field on the SKU page, so the SKU does not change; Google returns it only for English in the US and India, so it is usually absent. `priceRange`, `regularOpeningHours` and `websiteUri` were already in that mask through the Enterprise tier; `reviews` were already there with author attribution and dates (decision 9).
5. **Five new SKUs, named like the existing ones, default ceilings at 80 % of the free cap** (pricing page "Last updated 2026-09-28 UTC", read 2026-10-01, lowest paid band):

   | SKU (kit name) | Google SKU | Free / month | USD / 1,000 | Kit ceiling |
   |---|---|---|---|---|
   | `places.nearby_search.pro` | Nearby Search Pro | 5,000 | 32 | 4,000 |
   | `places.nearby_search.enterprise` | Nearby Search Enterprise | 1,000 | 35 | 800 |
   | `places.nearby_search.enterprise_atmosphere` | Nearby Search Enterprise + Atmosphere | 1,000 | 40 | 800 |
   | `places.text_search.enterprise_atmosphere` | Text Search Enterprise + Atmosphere | 1,000 | 40 | 800 |
   | `places.aggregate.compute_insights` | Places Aggregate API | 5,000 | 10 | 4,000 |

   - Why: the proposal's "three new SKUs" are three *calls* (Nearby, Text Search Atmosphere, Aggregate); Nearby bills three SKUs by tier, so the ledger has five rows. `places.nearby_search.*` follows `places.text_search.*`; the brief's `places.aggregate.compute_insights` is used as given. `MAPS_SKU_CEILINGS` and the `ceilings` option accept the new names (they go through the same `resolveCeilings`), and every new call reserves on the ledger before it is sent.
6. **Nearby `radiusMeters` is clamped, not refused**: above 50,000 → 50,000, at or below 0 → 1, each noted in the result's `notes`. A missing or non-numeric radius is refused (`BAD_INPUT`).
   - Why: the brief says "clamped to Google's limits"; a clamped radius still answers a sensible question. Other bad values (`maxResultCount` outside 1–20, unknown `rankPreference`, malformed or > 50 types, a type both included and excluded) are refused before the ledger, like `textSearch`'s `pageSize`.
7. **Options a search does not take are not sent, without an error, and are listed in `notSent`.**
   - Text Search sends: `pageSize`, `pageToken`, `languageCode`, `regionCode`, `includedType`, `strictTypeFiltering` (only together with `includedType`; alone it is listed in `notSent`), `openNow`, `minRating`, `priceLevels`, `rankPreference`, `includePureServiceAreaBusinesses`, `locationBias`, `locationRestriction`. Not sent: everything else (e.g. `center`, `radiusMeters`, `maxResultCount`, `includedTypes`).
   - Nearby Search sends: `center`, `radiusMeters`, the four type lists, `rankPreference`, `maxResultCount`, `languageCode`, `regionCode`. Not sent: `minRating`, `openNow`, `priceLevels`, `pageToken`, `pageSize`, `includedType`, `strictTypeFiltering`, `locationBias`, `locationRestriction` and any other key.
   - Why: the brief asks for "silently NOT sent otherwise (document which)". The `notSent` list makes the drop visible to a caller who shares one option bag across both searches, without failing the run. A value that *is* sent but malformed is still refused.
8. **Text Search filter validation.** `minRating` must be 0–5 in steps of 0.5 (4.3 is refused, not rounded: the proposal's 4.3 floor must be applied in the engine's screening or sent as 4.0 / 4.5 — see the status file's note to the engine). `priceLevels` accepts the five `PriceLevel` values (`FREE` … `VERY_EXPENSIVE`) in short or `PRICE_LEVEL_` form, deduped (the searchText reference: "Users can choose any combinations of price levels"; it names no excluded value). `locationRestriction` takes a rectangle `{ low, high }` only (a circle is refused with a hint to use `locationBias`); `locationBias` takes the existing circle or a rectangle; giving both is refused (searchText reference: each "Cannot be set along with" the other). `low` must be south of `high`; longitudes may cross the antimeridian.
9. **Reviews and summaries are returned, not reshaped in place.** `placeDetails` still returns Google's raw place (reviews carry `authorAttribution.displayName`, `.uri`, `.photoUri`, `publishTime`, `relativePublishTimeDescription`). Two pure helpers are added: `normalizeReviews(place)` and `placeEvidence(place)` (rating, `userRatingCount`, reviews, oldest / newest review time, review / editorial / generative summaries with their disclosure text, price level and range, hours, website, Maps link; absent fields are `null`).
   - Why: changing `placeDetails`' return shape would break Phase 3–4 callers; the engine's "unproven" flag needs review dates and the rating count, which `placeEvidence` exposes flat. Nothing is persisted (Maps terms §3.2.3; README "What it never does").
10. **Places Aggregate: circles only; regions and custom polygons are refused** (`MapsInputError`, nothing reserved or sent). Circle centre is `{ lat, lng }` (sent as `latLng`) or `{ placeId }` (sent as `place: "places/<id>"`); `radiusMeters` 23–50,000, rounded to an integer.
    - Why: proposal §2 fact 7 / §4 stream 3 — no point-in-polygon work on Google coordinates; cells are circles around our own anchors. 23 m is the smallest radius whose area clears Google's 1,556.86 m² floor; 50 km mirrors Nearby Search (Google states no maximum below 2 trillion m², but no funnel cell needs more). Unlike Nearby, the radius is refused rather than clamped: a silently clamped *count* would be a wrong answer to the question asked.
11. **Aggregate request and result.** `insights` must be a non-empty subset of `INSIGHT_COUNT` / `INSIGHT_PLACES` (no default). `typeFilter` needs at least one non-empty list of the four. `ratingFilter` needs `minRating` and/or `maxRating`, each 1.0–5.0, min ≤ max. `operatingStatus` takes `OPERATIONAL` / `TEMPORARILY_CLOSED` / `PERMANENTLY_CLOSED` in short or `OPERATING_STATUS_` form; `priceLevels` takes all five levels including FREE. The result is `{ count, placeIds, sku, ms }`: `count` is parsed from Google's int64 string (`null` when absent), ids lose the `places/` prefix and malformed ones are dropped. No field mask header (the method takes none).
    - Why: mirrors the REST reference exactly; one normalized shape for the engine. **Inference, not verified live:** asking `INSIGHT_PLACES` when more than 100 places match returns a Google error, which the kit surfaces as `HTTP_400`; callers should ask for the count first.
12. **The Aggregate host is not yet allowed; no new error type.** A live call before Phase 7 fails in the transport with the existing `PROXY_REFUSED` (proxy refuses `CONNECT`) or, if it connects without a key, Google's 403 maps to the existing `AUTH`. The ledger counts the attempt and annotates it `failed` (WP-2a decision 5). The live path stays behind the existing `--live` + ledger flags and was not exercised.
13. **CLI `nearby` and `aggregate` default to the fixture transport**; `--live` (with `--ledger` or `MAPS_USAGE_LEDGER`) switches to Google, exactly like `smoke`. Both take the call's params as `--json`; `nearby` also takes `--tier`. Output is the normalized result plus `source: fixtures|live`. `masks` now lists `nearby_search`, the Text Search Atmosphere tier and the Aggregate SKU.
    - Why: the brief asks for fixture-by-default commands that mirror the existing ones; `--json` mirrors `route` / `matrix`.
14. **Fixtures.** New hand-written files in Google's shapes for the invented city "Velmora" (open-ocean coordinates, ids prefixed `Fixture`, reserved `example.*` domains, currency `XTS` — the ISO 4217 code reserved for testing, review authors as handles): `nearby-search-enterprise`, `text-search-enterprise`, `place-details-atmosphere` (three reviews with authors and dates, review and editorial summaries, no generative summary, a price range), `aggregate-count` (37) and `aggregate-places` (3 ids). The mock transport picks the Text Search and Details fixture by the mask's tier and answers `computeInsights` from the requested insights, so existing tests see the same answers as before.

### Research kit

15. **Tags are entry-level, optional and caller-set.** `source_kind` ∈ `editorial` · `community` · `local-language` and `language` (BCP 47, canonicalized with `Intl.getCanonicalLocales`, ≤ 35 characters) on `record-search` / `record-fetch` and the library's `search(q, opts)` / `fetch(url, opts)` (`sourceKind` accepted as an alias). A search's tags apply to all its results. `record-api` entries are always untagged.
    - Why: the routine knows which kind of source it searched or fetched; a page must never set a field (README "never"), so the injected functions' return values are not read for tags.
16. **Bad tags exit 2 (usage) and spend nothing.** The CLI validates while building the entry, before anything is written; the library validates before the injected call runs.
17. **Schema: the two fields are optional properties of `ledgerEntry`** (`enum` with `null`, and a BCP 47 pattern), not `required`.
    - Why: run files written before this package must keep loading (the kit validates on every load). New entries always carry both keys, `null` when untagged; a hand-edited bad value is rejected like any other field.
18. **`mentions(run, { source_kind?, language? })` lists usable sources only** — status `ok`, not `injection_suspect` (per search result for snippets) — as `{ ref, kind (fetch|snippet), url, domain, publisher, source_kind, language, official }`. Filters: a kind or `untagged`; a language matches exactly or by primary subtag (`ja` ↔ `ja-JP`). Exposed as the library function, `session.mentions()` and the CLI command `mentions`. `summary` / `status` / `finish` add `source_kinds` (usable search and fetch entries per kind, plus `untagged`).
    - Why: the brief's minimum was `[{ ref, url, source_kind, language }]`; `publisher` lets the engine count *independent* local sources (proposal stage 3, "per independent local-language source") without re-deriving domains, and `kind` lets it weigh a fetched page above a snippet. Flagged sources never count, as everywhere else in the kit. The kit does no place matching.
