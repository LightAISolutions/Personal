# Industry Guidance Command

If the user says **"industry guidance: <document>"** (or similar: "add this to Industry Guidance", "analyze this document for the guidance hub", "new guidance doc", or uploads an industry-wide document with that intent):

1. **Ingest the source** — copy the uploaded document to `repository-information/industry-guidance/sources/<slug>.pdf` (kebab-case slug with publisher + topic + date, e.g. `nvidia-800vdc-white-paper-2026-08.pdf`). Image-only PDFs are read visually with the Read tool's `pages` parameter (PyMuPDF `get_text()` returning 0 chars on every page identifies them)
2. **Deep-read and verify** — read every page; extract all quantitative claims and dated milestones with page references; verify the numbers with at least one independent re-extraction pass (subagents assigned page ranges) before any figure enters the content. Respect the source's reproduction notice: analysis is original prose, quantitative claims carry page citations, figures are re-expressed from stated data — never reproduced as images
3. **Write the analysis markdown** — `repository-information/industry-guidance/<slug>-analysis.md` (never deployed; the source of truth). Standard shape: what the document is → executive read → known-vs-new map tailored to the developer's current curriculum → per-topic deep dives with advantages/disadvantages made explicit → "what it means for <active engagement>" → claims ledger (page-referenced) → what the document does NOT say
4. **Author the in-app module** — a new `guidanceDoc<Name>_()` function in the PROJECT block of `googleAppsScripts/Profiler/Profiler.gs`, registered in `guidanceDocs_()` **with a `group` meta field and a `reviewBy` meta field** (see step 10) — the topic-lane label the library view groups by (current lanes: `Technology Foundations`, `The AI Data-Center Wave`, `Market Access & Bankability`; add a new lane only when no existing one fits). Keep `guidanceDocs_()` ordered by lane so the index arrives grouped; `guidanceIndex_()` emits `group` and Profiler.html renders a header whenever the lane changes (2026-08-29). The module JSON's section kinds (`prose`, `callout`, `table`, `proscons`, `timeline`, `bars`, `flashcards`, `quiz`, `ledger`) plus `glossary`, `tiles`, per-section `sales` notes (rendered under a "Sales angle" label; renamed from `zh` 2026-08-29) and `{{term}}` tooltips are rendered by Profiler.html's guidance renderer — **new documents need no page changes**. Timeline lane colors are the CVD-validated trio (gold `#b18f35` generations/core, blue `#4f83e6` deployment/milestones, rose `#cc5f75` ecosystem); re-run the dataviz validator if new chart colors are introduced. Covered company names inside module text render automatically as dossier-linking chips (`gdLinkCompanies` — registry name authority + `ovRelDerive`'s ambiguity guard; quiz/done buttons, links, headings, glossary-term spans excluded) — no authoring action needed. The library view carries a client-side **search** over every module's flattened section text and glossary (`gdFetchAllDocs` caches all docs once per page load; hits open the module scrolled to the section) and a **unified glossary** view merging all modules' terms alphabetically with per-module definitions and source chips — both ride the existing role-gated ops, no authoring action needed. **Content scope (developer directive 2026-08-29): modules give guidance to supplier/buyer groups only** ("BESS suppliers", "TRU/SST suppliers", "§154-listed suppliers", "developers", "integrators", "hyperscalers"…) — never to a single named company (statutory facts naming companies, like the NDAA §154(b) list, are fine as objective information). Company-specific analysis reaches admins **inside** modules via the **Admin lens**: a report's `guidanceOverlays[]` anchors (PROFILER-SCHEMA.md → Report schema) render 🔒 panels in the anchored sections for viewers with the `reports` capability only — never as module content
5. **Access model** — the guidance ops (`action=guidance`, `gop=index|doc`) are **role-gated server-side** in `handleGuidanceOp_` via `guidanceAllowed_(sess)`: anything carrying the `admin` permission, plus the tiers listed in `GUIDANCE_ROLES` (currently `contributor`); everyone else gets `ROLE_DENIED`. The masthead button is created only for sessions whose tier holds the `guidance` capability in `OV_ROLE_CAPS` (UI convenience; the server check is the boundary) — see the Role + Access matrix in `.claude/rules/profiler-app.md`, and keep `GUIDANCE_ROLES` and `OV_ROLE_CAPS` in sync. Module content ships inside `Profiler.gs` — repo + GAS project only, never on public Pages. A third op, `gop=mentions` (same role gate), returns which modules mention each covered company from a 6h-cached server-side scan (registry fetched from Pages as the name authority, mirrored ambiguity guard) — it feeds the dossier-side "Covered in guidance modules" chip line, rendered only for tiers holding the `guidance` capability so module titles never reach other tiers
6. **Versioning** — content-only additions bump the **GAS** version ([PC-GS-VERSION] #1) since the module lives in `Profiler.gs`; renderer/UI changes also bump the **page** version ([PC-HTML-VERSION] #2). Standard Pre-Commit checklist applies; public page/GAS changelog entries stay generic ("guidance library updated") per changelog-security — never name the analyzed document publicly
7. **Verify before push** — `node --check` on a `.js` copy of Profiler.gs, `scripts/check-gas-inner-scripts.js`, and a Playwright render of the module via direct `gdRenderDoc()` invocation with the new JSON (auth bypassed with `bypass_csp` + localStorage role), plus the standard harness smoke test
8. **Refreshes** — a revised edition of a covered document updates the same module (bump its `updated` field), archives nothing (git history suffices), and amends any engagement docs the findings touch (e.g. the Zhonhen study-prep set), regenerating affected study-prep PDFs
9. **Scraper interest seed (authoring-time sync)** — the Scraper↔Profiler interest model syncs guidance topics at authoring time, not via a runtime probe (developer decision 2026-08-27): when registering a new guidance module, also add a matching topic seed to `SCRAPER_INTEREST_TOPIC_SEEDS` in `googleAppsScripts/Scraper/Scraper.gs` — `key: 'topic-<slug>'`, `label`, default search `terms`, `source: 'guidance:<module-id>'`. Scraper's daily registry sync upserts the seed into its Interests tab (default-ON, flagged "New topic") and the digest rubric scores against it. This touches `Scraper.gs`, so bump the Scraper GAS version too ([PC-GS-VERSION] #1)

10. **Freshness discipline (2026-08-29)** — every module carries a `reviewBy: "YYYY-MM-DD"` meta field, set at authoring from the module's **own nearest dated gate** (a regulatory effective date, a deployment milestone, a rate that changes on a schedule) rather than a fixed cadence; slow-moving fundamentals modules default to ~6 months from `updated`. `guidanceIndex_()` emits it, and Profiler.html renders it as a chip on the library cards and the module header (`gdReviewChip`: plain >30 days out, gold within 30 days, red "⚠ review due" once passed). Reports age independently: the report library and report view show an age chip from the report's date on the dossier freshness tiers — fresh ≤45d / aging ≤120d / stale (`rpAgeChip`); superseded reports get no chip. **The quarterly review Routine** — `Industry Guidance quarterly review` (`trig_01CrhxzfBV6uKQNKpUXLLMSZ`, cron `0 13 15 1,4,7,10 *`, fresh session per fire; armed 2026-08-29) — re-verifies each module's dated gates against primary sources, updates stale content (content-scope rule intact), refreshes `updated`/`reviewBy`, validates report overlay anchors via `check-profiler-reports.py`, and recommends superseding aged reports. When a module revision changes its dated gates mid-quarter, set the new `reviewBy` in the same commit — the Routine is the backstop, not the primary mechanism

**Q&A channels are deliberately v1-absent** (developer decision 2026-08-22). If revisited: `anthropicSummarize_` in Profiler.gs is the existing Claude API precedent (Script Properties `ANTHROPIC_API_KEY`/`ANTHROPIC_MODEL`) — read the `claude-api` skill before extending it.
